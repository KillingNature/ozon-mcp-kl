# Ozon shopping — практики этой сессии

Справочник по самим инструментам ozon MCP и поведенческие особенности Ozon
(три цены, «Купленные товары» ≠ полученное, буквальность поиска, снимок корзины
при входе в оформление и т.д.) уже приходят автоматически в system-инструкциях
при подключении сервера — дублировать их здесь незачем. Ниже — только то, что
в эти инструкции не входит: конкретные приёмы и грабли, накопленные на практике.

## Просмотр картинки по прямой ссылке

У меня нет тула «открыть URL картинки и увидеть её». Но есть рабочий обходной
путь, состоящий из двух обычных тулов:

1. `Bash`: `curl -sS -L -o <scratchpad>/img.jpg "<прямая ссылка на файл>"`
2. `Read`: `Read(file_path="<scratchpad>/img.jpg")` — вот тут картинка реально
   отображается и я её вижу.

Работает для любой прямой ссылки на файл изображения (не только `ir.ozone.ru`),
включая фото из `get_photos()` / `product_details().photos` и фото из отзывов.
НЕ работает так для HTML-страниц — это только для сырых файлов картинок.

Когда стоит этим пользоваться:
- сверка формы/силуэта/цвета товара с фото, которое прислал пользователь
  (унитаз, сиденье, ручка, мебель и т.п.) — сначала взять кандидатов через
  `get_photos`/`product_details`, скачать 1–3 фото и `Read`;
- нужно увидеть деталь, которую текст карточки не покажет (надпись на резинке,
  точная геометрия детали, цвет вживую);
- НЕ делать это по умолчанию на каждый товар — только когда решение реально
  висит на визуале, обычно после того как текстовое описание оказалось
  неоднозначным или уже один раз подвело.

## Ловушки, в которые я уже влетал — не повторять

1. **«Цвет»-вариант в карточке может означать совсем другой товар.**
   Один listing иногда группирует под «Цвет» реально разные типы (например,
   ручка-кноб и рычажная ручка одной серии защёлки). Прежде чем рекомендовать
   конкретный вариант — читать его `characteristics` (`Тип дверной ручки`,
   `Форма розетки` и т.п.), а не полагаться на текст названия цвета или на
   заглавное фото карточки.

2. **Название бренда не гарантирует материал.** Sagami продаёт и латекс
   (Miracle Fit), и полиуретан (Original 0.0x) под одним брендом. SKYN — не
   полиуретан, а полиизопрен, хотя часто воспринимается как «премиальный
   безлатексный полиуретан». Всегда сверять `Материал`/`Состав материала` в
   characteristics конкретного SKU, а не доверять бренду или общей категории.

3. **Поиск Ozon ловит мусор на многозначные слова.** «boxer» подмешивает
   автозапчасти для Peugeot Boxer, узкий бренд типа «JEX» подменяется
   случайными результатами при отсутствии точных совпадений. Всегда
   просматривать выдачу глазами и явно отбрасывать нерелевантное, а не просто
   брать первые N строк.

4. **Отзывы — лучший источник под узкий, конкретный вопрос.** Рейтинг и число
   отзывов говорят об общем качестве, но конкретную претензию («работает ли
   отпечаток пальца через это стекло», «есть ли надпись на резинке», «какая
   ширина крепления») находят текстовым поиском по содержимому отзывов.
   `get_reviews(sort="worst")` особенно полезен — там честные жалобы, которые
   не всплывают в среднем по больнице рейтинге.

5. **`purchases()` с широким запросом на аккаунте с большой историей** отдаёт
   сотни несвязанных строк, и `bought_items` не успеет разрешить статус
   получения за разумный `scan_orders`. Для простого «что я раньше заказывал
   по бренду X» обычно достаточно `purchases(query=...)` и прочитать список —
   не обязательно гнаться за `received`-статусом, если пользователю нужна
   только цена/наличие сейчас, а не факт получения.

## Стандартный workflow подбора товара

1. `search(query=..., sort=...)` — сузить релевантным запросом (модель, а не
   «бренд+модель» — поиск буквальный), глазами отсеять мусор из выдачи.
2. `product_details(sku)` — проверить цену/характеристики/материал/размер
   именно этого SKU, не доверять только тайтлу плитки.
3. `get_reviews(sku, sort="useful")`, а при необходимости и `sort="worst"` —
   искать в тексте отзывов конкретную претензию/подтверждение под запрос
   пользователя.
4. При визуальной неопределённости — скачать фото (`get_photos` + curl + Read)
   и сверить с референсом пользователя.
5. Явно обозначать пользователю, где я не уверен (маленькая выборка отзывов,
   неподтверждённое количество в упаковке, конфликтующие данные) — не выдавать
   догадку за факт.

## Лимиты этого сервера, которые стоит держать в голове

- Запись/заказы по умолчанию выключены (`OZON_ENABLE_WRITES` /
  `OZON_ENABLE_ORDERS`) — в этой сессии сервер read-only: добавление в корзину
  и оформление заказа недоступны, только просмотр и поиск.
- Один воркер на аккаунт, состояние корзины общее на стороне Ozon — если
  когда-нибудь запись включат, помнить, что параллельных пишущих агентов быть
  не должно.
